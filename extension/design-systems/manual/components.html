Manual / 2 Authenticating requests

2Authenticating requests

Every request carries a key in the Authorization header. Keys belong to one project and can be rotated without downtime.

2.1 Create a key

  1. Open Project settings → Keys.
  2. Choose New key and name it after the service that will use it.
  3. Store the key at once: it is shown only when it is created.
Note

Never ship a key in client-side code. Sign requests from a server you control.

2.2 Send the key

Pass the key as a bearer token. The examples read it from an environment variable named MANUAL_KEY.



2.3 Parameters


Authorizationheader · required
The word Bearer, a space and the key, for example Bearer mk_test_example.
X-Projectheader · optional
Chooses the project when a key can reach more than one.
expires_ininteger · optional
Seconds until a short-lived key expires, from 60 to 86400.


A missing or rejected key returns 401. Search this manual with / in the full product.
