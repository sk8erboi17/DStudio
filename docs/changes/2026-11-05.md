# Learn audit recovery and shared history — November 5, 2026

Learn now checks a finite list of content items with the actual saved source
text, saves each completed batch, and reuses only matching validated receipts.
Missing evidence remains unresolved. Stage-pair and stage/capstone checks retain
cross-stage consistency coverage. The retained six-stage private draft has not
completed the new audit; this update does not qualify a release or complete P3/P6.

## Implementation

- A deterministic plan covers every stage's content, topic concepts/application/
  resources, learner/capstone fields, every stage pair and every stage/capstone
  pair. Content jobs hold at most four items. Models inspect all claims within
  an item and return every requested id exactly once.
- External checks receive excerpts of pages actually read, or existing prepared
  text attachments. Discovery snippets and unread pages are excluded. Every
  supported/contradicted verdict needs a quote matching both the supplied excerpt
  and the saved source text. Consistency checks quote their supplied input.
  Unsupported claims are not silently passed. Low-confidence contradictions
  remain unresolved. Only precise high-confidence contradictions enter repair.
- Each batch is saved before the next starts. Receipt keys bind item text,
  selected full-source digests/excerpts, learner context, model/settings and
  protocol. Restored receipts are structurally and citation-validated again.
  Repairs recheck changed content batches and affected global pairs while
  reusing unchanged checks. An insecure LAN origin without WebCrypto recomputes
  checks instead of using a weak key.
- The repetition guard also detects substantially recurring normalized
  paragraphs even when reordered; it preserves numbers and does not judge
  elapsed time or verbosity alone. A repeated reasoning suffix is preserved
  privately and omitted from the retry prompt to avoid seeding the same cycle.
- Resource limits are explicit: 512 jobs, four content items per job, 8M
  plan/source characters, 2M receipt characters, bounded reasoning previews and
  three automatic phase attempts. Exhaustion retains an incomplete draft.
  There is no automatic elapsed-work or productive-reasoning token cutoff.
  [Detailed contracts and test commands](../../tests/docs/ui.md).
- Progress distinguishes saved checks from incoming text. A continuous stream
  flushes progress periodically; its trailing debounce can no longer postpone
  persistence indefinitely. Stream counters repaint even when the activity label
  is unchanged, with a continuous-stream browser regression. Request,
  cancellation and original input ownership
  are revalidated before publishing completed verdicts.

quotation, confidence and consistency rules. Unique valid checks are persisted

match the current model/settings/protocol/evidence keys, and the pending items

## Shared conversation storage correction

The next retained failure was storage, before inference: a roughly 5.1 MiB
history exceeded the browser's small `localStorage` quota despite ample free
SSD space. Nineteen rapid retries copied the six-stage draft and then failed
to save it. The old emergency path also discarded reasoning and shortened
transcripts, disabled unrelated preference writes, and treated an unchecked
native POST as insufficient for a Learn checkpoint. This shared Store affected
Chat, Agent, Cowork, Design, Learn/Tutor and workflow/steering pointers.

History now moves to IndexedDB after quota exhaustion, committing the new copy
before removing the obsolete browser key. No emergency text shedding remains.
The host uses one bounded writer outside its HTTP owner loop, checks JSON,
writes/syncs a temporary file, atomically renames it and syncs its directory.
Success is acknowledged only afterward. An error before rename preserves the
prior file and revision; a directory-sync error after rename reports uncertain
durability rather than success. Revision conflicts merge independent chats;
an active conversation changed in another window is retained locally and
refused for publication. A clear-history epoch prevents stale windows from
resurrecting cleared conversations.

Learn awaits each checkpoint and refuses Retry before appending another draft
when both storage paths fail. Chat/Research and Tutor check persistence before
dispatch; steering and GSA/RSA pointers await saves and revalidate ownership.
Settings no longer share a global history-failure disable flag. Loading reports
an unsaved adjusted configuration separately from an engine-start failure.

Scoped checks use real Chromium/WebKit storage and the real native host/file,
authored payloads and injected faults, without inference: quota migration across
all five modes and Tutor payloads, blocked cache/writer, serialized saves,
malformed revisions, disk/browser failures, restart, two windows and durable
clear. A native test reopens an 8 MiB file and verifies responsive control under
a deterministically blocked writer. Learn's simulated recovery case repeats
Retry three times with all writes denied: no new draft/model/research request,
then successful recovery once storage returns. Stop during a blocked admitted
save prevents research/inference after its late acknowledgement. A private replay preserves all
23 existing attempts, six saved stages and 46 checks as identical JSON values
through migration/reopen on both browsers. It never writes the live
store. The original nineteen failures remain retained.

The HTTP LAN test originally reached a user's existing engine on port 28000;
it now isolates its proxy destination on an unused test port. A workflow test's
obsolete forced-Max assertion now verifies its explicit saved Off selection.
Earlier failed receipts are retained. Native macOS and browser checks do not
qualify Windows/Linux durability, model answer quality or P3 KV reuse.
