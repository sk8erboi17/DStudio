## Defects found and corrected

- **Light flash at startup with the dark theme.** Since the history load
  became asynchronous, the saved theme was applied after the static shell had
  painted. A script in `<head>` now applies it before the first paint. Found
  through one WebKit failure of `test-ui-sidebar` under load; a test with a
  barrier on the history database covers it in WebKit and Chromium.
- **A test left behind by the November 5 Max decision.** The 27B case still
  expected no prompt when Max is selected; it now requires exactly the loop
  warning and no context or restart question.
- **Four live runners erased their previous receipts** (ASCII diagrams, math
  explanations, PDF RAG, Search/Research). Each run now owns a new directory.
- **The native common-100 runner read the engine revision with Git**, which
  fails on a bundled install; it now reads DStudio's source receipt and refuses
  an engine without one.
- **The maintainer's Laguna checkout was a legacy tree** without a receipt,
  whose sources differed from the pin. It was moved aside unchanged and Laguna
  was installed again from the bundled `448d569` sources.
- **Thirteen stale patch hashes in the admission manifest.** Seven patch and
  runtime files had changed without `docs/engine-upstream.json` being
  refreshed. A model-free check now keeps the manifest in step with the
  shipped patches and the app's installer pins.
- **No MLX model could be downloaded.** The Hub answers a pinned file URL with
  a redirect whose own body (about 300 bytes) is larger than the smallest
  files of an MLX folder (58 and 202 bytes), and curl applied the downloader's
  size limit to that redirect: `curl: (63) Maximum file size exceeded`. The
  first real MLX variant download of the campaign failed this way; the
  loopback fixtures had no redirect. curl's limit now leaves room for a
  redirect body, while the transfer loop still refuses any byte beyond the
  pinned size. Two regression cases reproduce the redirect (one with an
  oversized file behind it, which is still refused). The installed app keeps
  the old downloader until it is rebuilt.
- **An oracle helper that rejected every page.** See below.

A gate run with one receipt per target (`gate-runs/check-fast-h83qnj`,
120 of 122 targets passed) failed the same check in two targets while five
browser-driving jobs were running: in WebKit, opened from a local file, the
Design originals test read the focused element immediately after Escape
closed a dialog, and focus had not yet returned to the button that opened it
(Signal in one target, Tally in the other). The check now waits for that
button to be focused and then reads it; a page that never returns focus still
fails. The target passed alone before the change and after it (402 checks).

One `test-ui-workflow` failure (a ten-second wait for an admitted send, in
WebKit) happened once while weight hashing and a model run were starting. It
passed on rerun and in the next complete gate; no cause is established and the
failed log is retained.

## Codex CLI as the third competitor (protocol only)

The competitor runner gained a Codex harness and
`make test-codex-protocol`: the installed Codex CLI 0.167.0 runs 26 cases
against a scripted Responses server through the runner's own proxy,
configuration, command line and parser (tool call, real command and file,
tool result, answer; reasoning; split frames and split Unicode; identifiers;
resume; compaction; stop; malformed and truncated streams; sandbox; model pin;
isolation; graded benchmark tasks). It is an explicit target, not part of
`check-fast`, and says nothing about any model. No real-model Codex run exists
yet.

While the harness was being probed, the first two `codex exec` invocations ran
before the CLI's background connections were known: with default features it
attempts chatgpt.com, github.com and api.github.com. Those two runs used an
empty isolated home without credentials; what they sent is not known. Every
later run points the CLI's proxy variables at the local pin proxy, which
refuses and records anything that is not the local engine API, and the final
configuration made no such attempt.

One case failed intermittently after integration: the CLI runs commands in a
login shell, and with an isolated home `python3` resolved to the Xcode shim,
which cannot write its cache inside the CLI's sandbox, takes about ten seconds
and floods the output. The harness now gives that shell the same search path
as the other two harnesses; three consecutive runs pass 26/26.

## Design interaction oracles

All eighteen oracles now have an authored reference page with deliberate
faults, checked in Chromium and WebKit. Qualification found that the row
helper made two oracles reject every implementation; it is corrected, with
three smaller corrections for correct pages that were rejected. A second pass
then made each oracle detect the defects it had missed, where its brief
requires the behaviour, and accept the correct pages it had rejected: the
seventeen fixtures now hold 262 faults and 85 accepted variants, and the
complete test runs 863 checks. A third change corrected the five limits of
the shared helpers that the second pass had recorded (tabs with a count, rows
that hold a name inside a longer text, a title shown in two rows, a dialog
opener with a count, text capitalised by CSS) and moved the workarounds that
scenarios duplicated into the shared layer: the oracle file went from 1,980 to
1,882 lines, the fixtures hold 270 faults and 86 variants, and the complete
test runs 881 checks. Each correction has a variant the old helper rejected
and a fault the new one still rejects. The narrower limits that remain and the
behaviours still unverified are listed in
[the Design test guide](../../tests/docs/design.md#interaction-oracle-qualification).
These fixtures qualify the oracles, not a model.
