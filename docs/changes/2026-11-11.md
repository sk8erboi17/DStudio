# Campaign resumed: baseline, coordinator, first corpus results — November 10–11, 2026

On November 10 the owner resumed the macOS completion campaign
([PLAN.MD](../../PLAN.MD)), returned DeepSeek V4.1 Flash 1017 Q2 to the
maintainer's plan with expert SSD streaming only, and added two closing steps:
P12 (remove unnecessary complexity and really useless tests, proved by tests
over every usage case) and P13 (rewrite the README and re-record its media).
This note records what was done in the first two days. The campaign is not
complete: every phase stays open in the plan.

## Defects found and corrected

- **Light flash at startup with the dark theme.** Since the history load
  became asynchronous, the saved theme was applied after the static shell had
  painted. A script in `<head>` now applies it before the first paint. Found
  through one WebKit failure of `test-ui-sidebar` under load; a test with a
  barrier on the history database covers it in WebKit and Chromium.
- **A test left behind by the November 5 Max decision.** The 27B case still
  expected no prompt when Max is selected; it now requires exactly the loop
  warning and no context or restart question.
- **Four live runners erased their previous receipts** (ASCII diagrams, math
  explanations, PDF RAG, Search/Research). Each run now owns a new directory.
- **The native common-100 runner read the engine revision with Git**, which
  fails on a bundled install; it now reads DStudio's source receipt and refuses
  an engine without one.
- **The maintainer's Laguna checkout was a legacy tree** without a receipt,
  whose sources differed from the pin. It was moved aside unchanged and Laguna
  was installed again from the bundled `448d569` sources.
- **Thirteen stale patch hashes in the admission manifest.** Seven patch and
  runtime files had changed without `docs/engine-upstream.json` being
  refreshed. A model-free check now keeps the manifest in step with the
  shipped patches and the app's installer pins.
- **An oracle helper that rejected every page.** See below.

One `test-ui-workflow` failure (a ten-second wait for an admitted send, in
WebKit) happened once while weight hashing and a model run were starting. It
passed on rerun and in the next complete gate; no cause is established and the
failed log is retained.

## Tools added for the campaign

- `tests/live/quality_multihardware.mjs`: coverage of the ten selections from
  receipts, on the current engine pin, model and memory mode, and sequential
  start of the owning runner.
- `tests/live/host_common_quality.mjs`: the frozen corpus through the
  production host, for llama.cpp, MLX and expert SSD streaming.
- `tests/support/heavy_preflight.mjs`, `campaign_identity.mjs`: resource
  snapshot before a model starts and the identities bound into a receipt.
- `tests/support/test_census.mjs`, `gate_run.mjs`: which target reaches each
  test file, and a gate run with one receipt per target.
- `tests/support/usage_matrix.mjs`: validator of the usage-case matrix that
  P12 requires before anything is removed.
- `tests/support/quality_baseline.mjs` now covers MLX, the toolchain and the
  app bundles. The November 10 baseline hashed ten weight and component files
  (about 800 GB); all pinned ones match their recorded SHA-256. The linked MLX
  folder was missed by that capture and is covered by the corrected tool; its
  files are verified against the catalog in the MLX run receipt.

## Design interaction oracles

All eighteen oracles now have an authored reference page with deliberate
faults, checked in Chromium and WebKit (128 faults). Qualification found that
the row helper made two oracles reject every implementation; it is corrected,
with three smaller corrections for correct pages that were rejected. The
limits that remain, and the defects the oracles do not yet detect, are listed
in [the Design test guide](../../tests/docs/design.md#interaction-oracle-qualification).
These fixtures qualify the oracles, not a model.
