# September 5, 2026: model selection, Qwen3.6 and SSD fixes

Changes since `ebe323b`. These notes describe the source update, not a newly
published installer or a new model-performance benchmark.

## What changes for users

### Choose a model; DStudio chooses its engine

- The composer has a redesigned picker using DStudio's light/dark palette:
  search by model or quantization, file size, an explicit current-model group,
  keyboard navigation and a layout that fits smaller windows.
- The separate engine-branch selector is removed from the composer. Choosing a
  model selects its matching runtime. Encoder and draft files are not offered
  as chat models; cloud models and MiniMax H3 retain their own entries.
- Download progress stays in **Settings → Models**. The composer keeps the model
  name, including after reloads and during a background or paused download.
  Catalog refreshes preserve the picker's search and focus.
- Settings refreshes also preserve the selected download target. A new browser
  regression reproduces the old behavior that could reset Qwen3.6 to the first
  download option before confirmation; the fix keeps the user's actual choice.
- Switching models shows the loading screen before preparation begins. It stays
  visible during engine selection and loading, reports actual launch errors,
  prevents duplicate launch requests, and only labels a ready model **Running**.
  Canceling a confirmation does not launch a model.
- **Done** closes Settings even when an unrelated hidden field is invalid;
  settings continue to save automatically.
- The disabled SSD selector now explains Qwen's limitation and lists the
  DeepSeek/GLM models to load for expert streaming, with an **Open Models** button.
  Qwen's effective setting does not erase the saved preference for other models.

### Experimental Qwen3.6-35B-A3B Chat

- Added the separate `vagrillo/ds4` `qwen35moe-support` runtime, pinned to
  `60fca11f0c8b16ca50c757324dddd717ba043098`, in managed `ds4-qwen35/`.
  Despite the branch/directory name, the integrated model is **Qwen3.6-35B-A3B**,
  not Qwen 27B, and it is separate from Qwen3.8-Flash-Next.
- Download from Settings or `./download-model.sh qwen36-q6`. The exact supported
  Unsloth Q6_K_XL GGUF is **31.8 GB**. Python/curl resume a visible `.gguf.part`,
  verify size and SHA-256, and publish without overwriting another existing file.
  The model uses the existing shared `ds4/gguf/` store, not a duplicate copy.
- This is **macOS Metal, text Chat/native only**. It needs resident weights and
  no PLE. Only Qwen3.8 uses a separate SSD-backed PLE file.
- Agent/Cowork/Design, vision, expert SSD streaming, DSpark and prompt lookup are
  not enabled for this Qwen integration. Native full power is used while the
  other models' power setting is preserved. Profiling flags that skip model
  computation are cleared from the launched child environment.
- Disk KV checkpoints are disabled for this fork because they do not serialize
  its complete recurrent state. Chat history remains saved and the running
  model can reuse its live context. Experimental expert pruning stays disabled.

Source download, compilation, setup/catalog/selection, launch wiring and small-file
download integrity were tested. **No Qwen3.6 answer-quality or tokens/s claim is
made.** Existing Qwen3.8 benchmarks must not be attributed to this new model.

### PDF/image and SSD prompt failures

Two separate problems are fixed:

1. **Native vision mappings:** SSD streaming can replace the language model's
   mapped spans. The vision encoder and visual-router bias must remain usable
   afterward. The new reversible vision patch revalidates encoder mappings and
   accesses the router bias independently of those replaced spans. It does not
   change routing math or pretend an unread image was understood.
2. **Our GLM/M2 port's short-batch regression:** the shared DeepSeek SSD path
   incorrectly limited an entire batch to eight distinct experts. Each token
   selects only six, but a batch may select many more. A 139-token block selected
   30 and failed before GPU dispatch. The corrected batch-resource bound is
   384; the independent per-token limit stays unchanged. The fix retains the
   optimized SSD path and does **not** reduce the user's 128k context.

The UI no longer diagnoses every `metal prefill failed` as insufficient memory
or claims that it successfully unloaded models. Genuine reported Metal memory
errors remain distinct and the original engine details remain visible.

## Installation, migration and repository changes

- Both fixes are maintained as reversible patches under `patch/`, with hooks
  under `scripts/`; ignored engine checkouts are not vendored into this commit.
- The GLM/M2 hook recognizes the complete previously installed port and upgrades
  its wrong batch bound. `check` does not modify source, `restore` handles either
  version, and partial/drifted patches fail without overwriting unrelated edits.
- Setup and the Chat/Agent/Cowork/Design launch paths apply the relevant patches.
  Native and derived runtime freshness checks now detect Metal-only source
  changes, including subsecond timestamps. Design already tracks the source diff.
- The native engine, derived runtimes and local `.app` were rebuilt. Publishing
  this source does not hot-patch a running process or upload a new release asset.
- The project-layout guide and ignore rules include `ds4-qwen35/`. Model files,
  application bundles, private Discord data, logs and generated test evidence
  remain local and excluded from Git. New tests follow the existing
  `unit/`, `integration/`, `browser/` and `live/` layout.

## Regression coverage and its limits

The new tests execute production behavior, not source-string contracts:

- Browser interactions cover model selection, loading/cancellation/errors,
  Settings closing, SSD compatibility, Qwen launch/download wiring and download
  display isolation. Launcher responses are **simulated**; these are not model
  inference tests.
- Qwen setup/unit/HTTP tests check separate runtimes, model-store identity,
  unsupported modes and launch arguments. Downloader tests transfer small real
  HTTP files and cover resume, corrupt/incomplete files, symlinks and no-clobber
  publication. Missing dependencies are not passing results.
- The vision regression executes real encoder/router kernels before and after
  three span replacements. The unpatched build must reproduce six failures;
  patched encoder/router outputs must match their baseline exactly.
- The SSD regression reproduces the old port's actual kernel/layer failures,
  then exercises the same migration used by the app. Four synthetic GPU batches
  match an exact CPU oracle. Six **real-weight, first-layer** cases with
  1/2/139/760/761/1024 tokens match upstream outputs **bit-for-bit**, with a
  **128k context allocation and SSD on**. Existing GLM top-8/cache tests also run.
  This is not a 128k-token input test, full-model inference, BF16 equivalence or
  a complete rerun of the PDF conversation.
- Patch lifecycle, stale-binary rebuilds, frontend error classification and
  macOS bundle materialization have separate checks.

Commands and exact scopes are in [tests/README.md](../../tests/README.md).
Patch details are in the [GLM/M2 correction notes](../../patch/ds4-glm53-m2max/README.md)
and [vision mapping notes](../../patch/ds4-vision-streaming/README.md).
Raw evidence is kept in ignored `tests/.artifacts/`; model weights and personal
PDF contents are never included in these change notes.

### PDF citation JSON and repeated labels: corrected with Poppler

A model can repeat the same citation ID (for example `P1`) for different
passages. The previous parser required unique IDs and rejected that entire
evidence block, leaving internal JSON visible and references unclickable. This
was reproduced with synthetic input through the production parser.

The parser now retains distinct passages sharing a label, deduplicates identical
entries and hides internal metadata even when malformed or truncated. Valid
citations survive an invalid sibling entry; unavailable details show an explicit
warning and are not treated as verified. Raw chat storage is preserved so saved
replies can recover their links when displayed by the updated UI.

Clicking a repeated label opens the existing **Poppler** modal with a passage
chooser. Selecting a passage requests its original physical page and checked
coordinates. No page/quotation is chosen arbitrarily; unattached document IDs
cannot be opened. Rapid selection changes cancel the old request and stale
responses cannot overwrite the current image/highlights. Calculations using a
label that denotes multiple passages remain explicitly unverified. The model
instructions now distinguish passage IDs from page numbers.

No MuPDF.js dependency, new model or OCR service was introduced. Tests exercise
real Poppler PDFs/HTTP/geometry in Chromium and WebKit, plus full-app streaming
and reload with a simulated repeated-label answer. Personal PDFs are not used
as committed test fixtures.

## Checks run before publication

### Follow-up: headless first-launch coverage

The real bundled executable now has a first-launch E2E gate with an empty data
profile and headless WebKit. It installs all four pinned engine checkouts through
actual first-run/model-download UI controls, checks executable startup and
automatic model-to-engine selection, and verifies all six main runtime patches
with an exact source round-trip on a private copy. Optional-engine source setup
is real; the later weight-download boundary is deliberately refused. No model
answer is simulated or counted as inference by this installation gate.

The test exposed two isolation problems, now fixed: source installation no
longer kills unrelated listeners on the inference port, and an explicit
`DS4UI_DATA_DIR` also isolates the chat store instead of reading/writing the
legacy host store. The default user chat-storage path is unchanged. Shutdown
only signals owned engines. Regression coverage uses real persistence and child
processes, and the E2E requires an existing listener/sentinel to remain alive.

The successful run is retained locally as `first-launch-TxNHSH`: main 45.1 s,
Laguna 30.3 s, Qwen3.8 19.0 s, Qwen3.6 13.2 s for this run's UI-triggered source
installation and checks. These are not inference speeds or universal install
times. Earlier failed harness attempts remain in the ignored artifacts.

The commands and the separate heavyweight installed-model gate are documented
in [tests/README.md](../../tests/README.md).

The follow-up real-model sweep loaded all nine supported installed chat models.
Eight passed all HTTP/Chat checks in the original sweep; Qwen3.8's exact streamed
answer was correct but the test sampled the DOM before rendering finished.
The targeted rerun with a displayed-answer wait passed all three checks. Both
reports are retained. See [the model-by-model results and limits](../HEADLESS_E2E.md)
for the 8k context and SSD/resident configurations; this does not qualify 128k or
multimodal/Agent behavior.
