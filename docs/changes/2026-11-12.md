## Laguna: two engine defects, fixed and measured

Laguna failed every long text of the common-100 corpus with the macOS GPU
error `kIOGPUCommandBufferCallbackErrorImpactingInteractivity`. Two defects in
the pinned Laguna engine caused that and a nondeterminism found on the way; both
are fixed in [`patch/ds4-laguna-prefill-chunk`](../../patch/ds4-laguna-prefill-chunk/README.md):

- Prefill attention gave each query one GPU thread group that walked every
  earlier key serially; walks of about 20,000 keys are what macOS ends.
  Smaller prefill batches alone still failed at token 20,480. Attention now runs
  in passes of at most 4,096 keys, with each query's softmax state kept
  exactly between passes.
- The sliding-window ring commit wrote a whole batch into 512 slots in one
  dispatch, so a slot kept an unspecified row and two runs of one prompt could
  differ. Each slot is now written once.

On real weights the patched engine's final logits are bit-identical to the
unpatched engine's, greedy decoding is identical across batch sizes and
repeated runs, and 40,153- and 60,689-token prompts complete
(`make test-laguna-prefill-chunk-live`). The installer, every Chat launch,
local pi/OpenCode launches and the Agent/Cowork/Design builds apply the patch;
a Laguna `ds4-server` built without it is rebuilt with `make -B`, because a
binary copied back can be newer than its sources
(`make test-laguna-prefill-chunk-upgrade`). The installed engine, upgraded by
the app's own Chat launch, answered a 40,153-token prompt through `/v1`, and
its counted common-100 is **62/100 with every task run** (51/100 with 12 not
run before): long texts 6/8, missing information 5/5, every other category
unchanged ([report](../benchmarks/quality-multihardware/README.md)). pi and
OpenCode now run on Laguna (3/6; one wrong answer, two confinement cases not
exercised because the model attempted no read).

The campaign coordinator now records a change of DStudio's own adaptations of
a pinned engine (`identityChanges`), so results on the earlier Laguna engine
are listed but not counted for the patched one.

## Usage cases: 51 of the 54 uncovered now have a test

Agents working in separate worktrees wrote behavioural tests for the uncovered
cases of the P12 usage matrix (model-free or labelled simulated; real-model
runners for four more), and the matrix records why the last three cannot be
exercised here. It now reads 627/629 cases with a test. Writing them found
these product defects, each fixed with a test that failed before:

- Chat announced "Response completed" to screen readers for an answer cut at
  the token limit or ended by an error.
- A harness bridge stayed up after pi or OpenCode died, so later prompts
  stayed "working" forever.
- GSA and RSA started on a pi/OpenCode Agent although they can never advance
  there; they are now refused with a reason.
- A long skill was saved cut to 32 KiB with a success reply, and every save
  added a trailing newline.
- Design's remote turn loop sent another model request after `question()`,
  `propose()` or a registered artifact, refusing the user's answer meanwhile.
- Blueprint silently returned to its blank form when a map turn saved no
  file, and its JSON export saved the group overview instead of the
  blueprint.
- The Design canvas zip export archived the host's "file too large" error as
  file content.
- A failed model download did not say why (a full disk read "Download or
  verification failed").
- With the cloud selected and no key, Chat answered with the local model.
- Pages that could not be read (refused, dropped, 403/5xx) were counted as
  evidence with the error text as content.
- Offline Deep Research asked the model to answer from memory.
- A password-protected PDF was reported as having no pages and the turn was
  sent anyway; page numbers above 2,000 got the wrong error.

## Other defects found and fixed

- Deep Research opened any address its planner asked for, so a page with
  instructions aimed at the model could make it fetch an address carrying
  data; reads are now limited to addresses the run discovered or the user
  gave (`make test-web-research-host`).
- The real remote suite showed that a remote ds4 model's tool call was
  refused: ds4-server sends a DSML call again as `tool_calls`, and the client
  host published that copy to a runtime that had asked for text. The host now
  delivers it once, as text, and the remote DSML Agent path emits the tool
  records the automatic Task Graph needs. A rerun on weights is queued.
- `DS4UI_ENGINE_PORT` redirected only the `/v1` relay of an isolated host;
  launches, external-engine detection and the doctor still used port 28000.
- The Design project auditor exempted deliberately hidden text only under the
  class name `.sr-only`, failing the same `.visually-hidden` rule and an
  off-page skip link; it now recognises them by how they render.
